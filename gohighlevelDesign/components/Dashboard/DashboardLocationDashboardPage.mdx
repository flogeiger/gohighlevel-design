# Location Dashboard — CSS Dokumentation

Das **„Dashboard"** (`Section 98`) ist die zentrale Reporting-Übersicht und über den Dashboard-Eintrag in der Hauptnavigation erreichbar. Es zeigt Widget-Cards mit Charts, Tabellen und KPIs. Die Seite hat zwei Modi (View / Edit) sowie mehrere teleportierte Popovers.

| Sub-Section | Beschreibung | Scope |
|---|---|---|
| **98** | Widget-Cards, Toolbar (Edit-Modus) | `#dashboard-wrapper` |
| **98b** | Header View-Modus, Dashboard-Switcher Button | `#location-dashboard-header` |
| **98c** | Dashboard-Switcher Popover | `#location_dashboard-popover_content-dashbaord_selector` |
| **98d** | Widget Date Property Popover | `.location-dashboard_popover--opportunity-status-date-property-content` |

**Scope:** `#dashboard-wrapper`

## Besonderheiten

- **Zwei Modi** — Der Header unterscheidet zwischen View-Modus (98b: Dashboard bearbeiten + Switcher) und Edit-Modus (98: Stornieren + Speichern + Widget hinzufügen). Die Button-IDs wechseln je nach Modus.
- **`#location-dashboard_btn--save-dashboard`** — Abweichend vom Standard: „Änderungen speichern" ist ein **outlined wine** Button (kein Primary), da „Widget hinzufügen" die primäre Aktion im Edit-Modus ist.
- **Teleportierte Popovers** (98c + 98d) — Beide Popovers werden zu `<body>` teleportiert. Scoping via `:has()` auf den inneren Container.
- **Dashboard Dropdown Options** — Werden über `[id^="location_dashboard-dashboard_option-"]` attribut-basiert gescopert da die IDs dynamisch erzeugt werden.
- **Widget Charts** — Die Diagramm-Farben (Kreisdiagramm-Blau, Balken etc.) werden nicht überschrieben — diese sind semantische Datendarstellungen.
- **Typo im GHL-Selektor** — `#location_dashboard-popover_content-dashbaord_selector` enthält einen GHL-seitigen Tippfehler (`dashbaord` statt `dashboard`). Der Selektor muss exakt so geschrieben werden.
