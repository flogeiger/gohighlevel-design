# Sammlungen (Collections)

Die **Sammlungen**-Seite (`#collections`) gruppiert Produkte in Kollektionen. Sie verwendet **Highrise UI** (`hr-*`-Klassen) statt NaïveUI — ein wichtiger Unterschied zu allen anderen Payments-Seiten. Die Seite enthält eine Highrise DataTable mit Pagination, Per-Page-Dropdown und Aktions-Icons. Der **Collection Editor** (`#create-collections`, Section 117b) bietet ein Formular mit Name, Bild-Upload-Zone und SEO-Feldern.

## Besonderheiten

**Highrise UI statt NaïveUI:** Diese Seite verwendet `hr-*`-Klassen (`hr-data-table__*`, `hr-button__*`, `hr-base-selection`, `hr-pagination-*`) — kein `n-data-table-*`, kein `n-button__border`. Button-Border-Fixes laufen über `.hr-button__border` und `.hr-button__state-border` statt `.n-button__border`.

**Doppelter Pagination-Fix für aktive Seite:** Die aktive Seitenzahl wird über zwei Selektoren gesteuert — einmal via `.hr-pagination-item__active .hr-button p` (Textfarbe) und einmal via `button[data-v-36320aab]` (Border). Beide sind nötig, da GHL die Border über einen Vue-Scoped-Selektor setzt.

**`#save-btn` nicht auf Editor-Root beschränkt:** Die ID `#save-btn` ist global — ohne zusätzlichen Parent-Scope würde der Style auf jeden „Save"-Button mit dieser ID wirken. Da GHL Seiten lazy rendert, ist dies in der Praxis unproblematisch.

**Upload-Zone via Attribut-Selektor:** Die Bild-Upload-Zone hat keine ID oder semantische Klasse — sie wird über `.border-gray-300[role="button"]` angesteuert, was die Kombination aus Tailwind-Klasse und ARIA-Rolle als Anker nutzt.
