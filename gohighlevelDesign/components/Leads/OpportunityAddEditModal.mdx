# Add / Edit Opportunity Modal — CSS Dokumentation

Das **„Gelegenheit Hinzufügen / Bearbeiten"** Modal ist zu `<body>` teleportiert und wird über `+ Hinzufügen Gelegenheit` auf der Opportunities-Seite geöffnet. Es besteht aus einem gemeinsamen Shell/Header/Footer sowie mehreren Tab-Panels.

| Section | Tab | Scope |
|---|---|---|
| **83** | Modal Shell, Header, Formular, Tags Popover | `.hr-modal:has(.crm-opportunities-modal-header)` |
| **82c** | Aufgaben Tab | `#task-container-opportunity` |
| **82d** | Notizen Tab | `#notes-container-opportunity` |
| **82e** | Zahlungen Tab | `.crm-opportunities-modal-tab-payments` |
| **82f** | Verknüpfte Objekte Tab | `.crm-opportunities-modal-tab-associations` |

---

![Add Opportunity Modal Screenshot](/add-opportunity-modal-screenshot.png)

## Übergreifende Besonderheiten

- **Teleportiertes Modal** — kein Parent-Context vorhanden, daher `:has()` als Scope-Ersatz zwingend nötig.
- **Teleportierte Dropdowns** (`.hr-base-select-menu`, `.v-vl-visible-items`) — werden global gescopert, da kein Parent-Selektor möglich.
- **„Alles löschen"-Button** in Filter-Popovers — GHL setzt `--n-border` via `.ui-button.hr-button--default-type` mit `!important`. Fix: ID + Klasse kombinieren für gleiche Spezifität (`button#[id]`).
- **Tailwind-Klassen** in der Sidebar (`bg-blue-50`, `text-blue-700`) — direkter Color-Override nötig, keine NaïveUI-Vars verfügbar.
- **Tags Popover** hat keine eigene ID — Scope ausschließlich über `.oppo-tags-select-popover`.
- **82c und 82d** teilen die gleichen Pattern — nur die Scope-IDs unterscheiden sich (`#task-container-opportunity` vs. `#notes-container-opportunity`).
